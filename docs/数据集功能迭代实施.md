# 数据集功能迭代实施文档

  ## 目标与执行顺序

  在现有“导入→生成→审核→导出”链路上，依次补齐 生成前预览、问题样本修复、质量概览、批量导入与精细导出。每阶段完成并验收后再进入下一阶段。

  这是 docs/PROJECT_SPEC.md 中部分“后续方向”的实施计划。开始开发时，先更新产品需求和 docs/PROGRESS.md，明确本轮范围。

  ## 第一阶段：生成前预览与少量试生成

  **用户流程：**上传文件并设置字段、切分方式、提示词和模型 → 查看文档数、Chunk 总数、前 20 个 Chunk 及长度 → 可选择最多 3 个 Chunk 试生成 → 检查样本与校验问题 → 确认后开始完整构建。试生成可以跳过。

  - 新增 POST /api/projects/preview：接收与现有构建接口相同的文件及解析、切分参数，复用同一套 Parser 和 Splitter；返回总数、前 20 个 Chunk、预计模型请求次数。预览不创建项目、不写数据库、不调用模型。
  - 新增 POST /api/projects/preview/generate：重新接收文件及配置，核对预览返回的文件和参数指纹，只对用户选中的最多 3 个 Chunk 调用现有 Generator、Cleaner、Validator；返回临时样本及问题，不入库。
  - 页面在文件或配置变化后清除旧预览与试生成结果。试生成必须由用户点击触发。用 Chunk 数和模型输出上限展示请求量上界，不把它称为准确费用。
  - 服务明确返回额度不足时，停止后续模型请求，保留已完成结果并提示用户；普通限流沿用有限重试。不得使用重置卡。

  **验收：**预览与正式构建对同一文件产生相同的 Chunk 顺序；预览不产生模型请求或项目记录；试生成最多请求 3 个 Chunk；错误能指出文件、字段或切分参数。

  ## 第二阶段：筛选审核与定向重生成

  **用户流程：**按审核状态、校验状态、来源和关键词筛选 → 查看问题及来源 Chunk → 编辑样本，或对该 Chunk 点击“重新生成” → 审核新样本。

  - 新增服务端分页查询 GET /api/projects/{id}/samples/search，参数为 page、size、review_status、validation_status、is_deleted、source_document_id、issue_rule、keyword；返回 {items,total,page,size}。保留现有列表接口供旧调用使
    用。

  - 新增 POST /api/projects/{id}/chunks/{chunk_id}/regenerate。使用原任务保存的生成方式、提示词及模型配置，建立一条标记为 regenerate 的运行记录；同一 Chunk 同时只允许一个重生成任务。
  - 只有新生成结果中至少有一条通过结构校验，才将该 Chunk 的旧样本标记为“已替代”。新样本从“待审核”开始；失败时旧样本保持原状。历史样本可查看，但默认列表与导出排除已替代样本。
  - 为样本增加 superseded_at 及所需索引，通过 Alembic 迁移；既有数据默认未被替代。已经生成的导出文件保持原样。

  **验收：**筛选总数与翻页一致；重生成失败不影响旧样本；成功后新旧样本及来源可追踪；导出不包含已替代样本。

  ## 第三阶段：零模型调用的质量概览

  在项目页增加“数据概览”，通过 GET /api/projects/{id}/quality-summary 按需统计：Chunk 成功与失败数、样本审核与校验状态、常见校验问题、精确重复数、消息长度分布、来源文档占比，以及当前可导出数量。统计口径默认排除已删除和已替代
  样本，并在页面标明口径。

  本阶段不做模型打分，避免把主观分数误显示为事实质量，也避免页面加载时产生模型费用。

  **验收：**概览数字能与筛选列表和实际导出数量对上；编辑、审核、删除或重生成后重新读取可得到更新结果；打开页面不调用模型。

  ## 第四阶段：批量导入与精细导出

  - **多源文件构建：**新建页面允许一次选多个受支持文件，为 JSON/JSONL/CSV 分别配置内容字段。先校验全部文件，再创建一个项目和构建任务；各文件分别保留 SourceDocument，进度汇总到同一任务。
  - **已有训练样本导入：**支持 Alpaca、ShareGPT 的 JSON/JSONL。导入时转换成统一 IR，每条记录保留文件名和行号，并建立对应 Chunk 血缘；重新执行清洗与校验，审核状态统一为“待审核”。格式错误返回明确的文件和行号，不静默跳过。
  **验收：**多文件样本能追溯到正确来源；外部样本导入后不能绕过审核；相同种子重复导出的划分一致；同一 Chunk 的样本不会分到不同文件；大数据量 JSONL 导出仍不一次性加载全部样本。

  ## 交付与验证要求

  每阶段由负责模型先阅读仓库 AGENTS.md、产品需求、架构和进度文档，只改该阶段所需内容。修改行为须配套 Fake LLM 测试；数据库相关集成测试遵守仓库的数据库工具限制。完成时运行 uv run ruff check .、uv run pytest 和 pnpm build，如有
  环境阻断须如实记录。每阶段交付可操作页面、接口、测试结果及更新后的进度文档；不代用户执行任何 Git 修改操作。
