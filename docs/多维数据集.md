  # 多维数据集扩增阶段

  ## 结论

  基于现有优质样本进行 LLM 扩增，当前价值高于继续完善精细导出。实现方向确定为：

  - 仅使用“审核通过、校验通过、未删除、未被替代”的样本作为种子。
  - 在当前数据集内生成扩增样本，结果统一进入待审核状态。
  - 用户选择扩增策略、目标新增总数、模型以及已有模板或临时自定义提示词。
  - 清洗、精确去重、结构校验后自动补生，最多尝试目标数量的 2 倍。
  - 保留“扩增样本 → 父样本 → Chunk → SourceDocument”完整血缘。

  调研取舍：

  - 借鉴 Distilabel 的策略化任务和结构化输出，但不引入其完整流水线依赖。
  - 借鉴 Augmentoolkit 的扩增数量与内容权重控制。
  - 借鉴 DataDreamer 的可恢复、可复现任务设计。
  - Bonito 的多任务类型值得参考，但其专用模型和 vLLM/Transformers 依赖不符合当前 OpenAI Compatible 架构。
  - 不引入训练、RAG、向量数据库、语义去重或第二次 LLM 裁判。

  ## 核心实现

  ### 扩增策略

  第一版提供五种可多选策略，每条生成任务只有一个主策略，便于控制分布：

  - 表达改写：保持知识不变，改变提问和回答表达。
  - 认知角度：从定义、原因、过程、比较、影响等角度提问。
  - 难度深化：增加约束、推理步骤或信息组织要求，但不得引入外部事实。
  - 角色视角：面向初学者、专业人员、决策者等不同受众。
  - 场景应用：将原知识改写为具体使用场景或问题解决任务。

  生成提示由固定的事实约束、所选策略、模板或自定义要求、结构化输出格式共同组成。自定义内容不能覆盖血缘、输出结构和禁止编造的约束。

  ### 数量调度与质量控制

  - 目标新增数量范围为 1–1000，默认 100。
  - 种子支持按来源文档和关键词筛选，预览时展示命中种子数。
  - 按“种子 × 策略”轮询分配生成数量，避免少数样本或策略占据全部结果。
  - 单次模型请求为同一种子和策略生成最多 3 条，复用模型并发限制。
  - 项目级精确去重同时覆盖原样本和本次扩增结果。
  - 无效、重复或缺失输出触发补生；累计请求样本数达到目标的 2 倍后停止，并明确展示实际有效数量。
  - 单个任务失败不影响其他任务；模型额度不足时停止未开始请求并保留已完成结果。

  ### 数据与任务结构

  新增可空字段：

  - training_samples.parent_sample_id：父样本自关联外键。
  - training_samples.generation_run_id：关联本次扩增任务。

  新增 augmentation_jobs，记录运行、种子样本、策略、请求数量、轮次、状态、有效数量和错误信息，用于进度、失败定位和中断恢复。迁移只增加可空字段和新表，不改写现有数据。

  PipelineRun.configuration 保存任务类型、筛选条件、种子指纹、策略、目标数量、模型签名、提示词快照和尝试上限。扩增样本 metadata 保存策略、模板和生成轮次等辅助信息。

  ## API 与界面

  新增接口：

  - POST /api/projects/{project_id}/augmentations/preview
      - 输入筛选条件、策略、目标数量、模型和提示词配置。
      - 不调用模型。
      - 返回种子数量、策略分布、预计调用次数、最大尝试量、输出 Token 上界和种子指纹。

  - POST /api/runs/{run_id}/retry
      - 仅重试扩增任务中未完成或失败的 Job。

  项目页增加“扩展数据集”主操作，打开独立大尺寸 Dialog：

  - 左侧集中放种子筛选、策略多选、模型和提示词。
  - 右侧实时展示种子规模、目标数量、策略分配和调用上界。
  - 模板与临时自定义提示词互斥选择。
  - 启动后复用项目进度区域，并明确显示“有效新增 / 目标数量 / 已尝试”。
  - 样本列表和详情标记扩增策略，详情可查看父样本及原始 Chunk。
  - 质量概览增加原始样本与扩增样本数量，不新增装饰性卡片墙。
  - 桌面端采用左右工作台布局；移动端转为单列，底部固定确认区，保证键盘操作和焦点可见。
