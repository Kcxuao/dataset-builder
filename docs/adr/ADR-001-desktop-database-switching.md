# ADR-001：桌面版数据库切换配置

## 状态

已采用。

## 背景

桌面发布包默认使用 SQLite，但普通用户需要在界面中切换至 PostgreSQL。连接配置不能保存在当前业务数据库中，否则切换目标数据库后无法稳定读取；运行中的 SQLAlchemy Session 也不适合热替换。

## 决策

- 将候选连接配置保存为用户数据目录下的 `database.json`，与业务数据库解耦。
- 页面区分“当前数据库”和“重启后数据库”；保存配置不切换当前连接。
- 保存前再次执行连接测试，测试成功才写入配置。
- 桌面入口在创建 FastAPI 应用和执行 Alembic 迁移前读取配置。
- API 永不返回密码；编辑 PostgreSQL 配置时，密码留空表示沿用已保存密码。
- 配置文件在 POSIX 系统使用 `0600` 权限；Windows 依赖用户专属的 `%LOCALAPPDATA%` 目录权限。
- 数据库之间不自动复制项目，界面明确引导用户先导出、重启切换、再导入。

## 未采用方案

- 将连接配置保存到业务数据库：存在自引用和切换后不可读问题。
- 运行时热切换 Session/Engine：后台任务和请求可能仍持有旧连接，状态边界不可靠。
- 自动复制全部业务数据：需要冲突处理、事务恢复和版本兼容机制，超出当前范围。

## 影响

切换必须重启软件；新目标数据库会在启动时自动执行 Alembic 迁移。数据库在保存后变得不可用时，启动仍会失败，用户需要恢复数据库服务或修正用户目录中的连接配置。
